1. ЦЕЛЬ РАБОТЫ
Освоить основы объектно-ориентированного программирования на языке PHP на практике. Научиться создавать собственные классы, использовать инкапсуляцию для защиты данных, разделять ответственность между классами, а также применять интерфейсы для построения гибкой архитектуры приложения.
2. ПОСТАНОВКА ЗАДАЧИ 
В соответствии с условием лабораторной работы необходимо разработать приложение для управления банковскими транзакциями с использованием объектно-ориентированного подхода.
Приложение должно обеспечивать следующие возможности:
1.	Хранение банковских транзакций.
2.	Добавление новых транзакций.
3.	Удаление транзакций.
4.	Поиск транзакций.
5.	Сортировка транзакций.
6.	Выполнение вычислений над коллекцией транзакций.
7.	Вывод данных в виде HTML-таблицы.
Для выполнения задания необходимо использовать строгую типизацию, классы, приватные свойства, конструкторы, getter-методы и интерфейсы.
3. ОПИСАНИЕ РЕАЛИЗАЦИИ
3.1. Включение строгой типизации
В начале PHP-файла была включена строгая типизация:
declare(strict_types=1);
Строгая типизация позволяет контролировать типы передаваемых аргументов и возвращаемых значений методов. Это помогает обнаруживать ошибки, связанные с неправильными типами данных.
3.2. Класс Transaction
Класс Transaction предназначен для описания одной банковской транзакции.
Он содержит следующие свойства:
•	id - уникальный идентификатор транзакции;
•	date - дата транзакции;
•	amount - сумма транзакции;
•	description - описание платежа;
•	merchant - получатель платежа.
Все свойства объявлены как private. Значения задаются через конструктор, а для получения данных используются getter-методы.
Также реализован метод getDaysSinceTransaction(): int, который вычисляет количество дней с момента совершения транзакции до текущей даты.
3.3. Класс TransactionRepository
Класс TransactionRepository отвечает за хранение коллекции объектов Transaction и выполнение базовых операций доступа к данным.
В нём реализованы следующие методы:
•	addTransaction() - добавление новой транзакции;
•	removeTransactionById() - удаление транзакции по идентификатору;
•	getAllTransactions() - получение полного списка транзакций;
•	findById() - поиск транзакции по ID.
Массив транзакций является приватным свойством класса. Прямой доступ к нему извне не предусмотрен.
3.4. Класс TransactionManager
Класс TransactionManager отвечает за выполнение вычислений и бизнес-логику приложения.
Он получает репозиторий через конструктор и использует его для получения коллекции транзакций.
Реализованы следующие методы:
•	calculateTotalAmount() - вычисление общей суммы всех транзакций;
•	calculateTotalAmountByDateRange() - вычисление суммы за определённый период;
•	countTransactionsByMerchant() - подсчёт количества транзакций по получателю;
•	sortTransactionsByDate() - сортировка транзакций по дате;
•	sortTransactionsByAmountDesc() - сортировка транзакций по сумме в порядке убывания.
Таким образом, хранение данных и выполнение вычислений разделены между разными классами.
3.5. Класс TransactionTableRenderer
Класс TransactionTableRenderer предназначен для отображения транзакций в HTML-таблице.
Метод render(array $transactions): string принимает массив транзакций и возвращает HTML-код таблицы.
Таблица содержит следующие столбцы:
1.	ID транзакции;
2.	дата;
3.	сумма;
4.	описание;
5.	название получателя;
6.	категория получателя;
7.	количество дней с момента транзакции.
Класс объявлен как final, чтобы запретить его наследование.
3.6. Создание начальных данных
Для проверки работы программы были созданы 10 начальных объектов класса Transaction.
Каждый объект содержит идентификатор, дату, сумму, описание и получателя платежа.
Начальные объекты добавляются в TransactionRepository, после чего используются для отображения и выполнения вычислений.
3.7. Интерфейс TransactionStorageInterface
Для повышения гибкости приложения был создан интерфейс TransactionStorageInterface.
Он определяет методы:
•	addTransaction(Transaction $transaction): void;
•	removeTransactionById(int $id): void;
•	getAllTransactions(): array;
•	findById(int $id): ?Transaction.
Класс TransactionRepository реализует данный интерфейс.
В свою очередь, TransactionManager принимает через конструктор тип TransactionStorageInterface, а не конкретный класс репозитория.
Это позволяет использовать разные способы хранения транзакций без изменения основной логики приложения.

                                         Ответы на контрольные вопросы 
1. Зачем нужна строгая типизация в PHP и как она помогает при разработке?
Строгая типизация нужна для контроля типов данных. Она помогает избежать ошибок, когда вместо одного типа данных передаётся другой.
В данной лабораторной работе используется директива declare(strict_types=1);, а также указываются типы параметров и возвращаемых значений методов.
2. Что такое класс в объектно-ориентированном программировании и какие основные компоненты класса вы знаете?
Класс - это шаблон для создания объектов. Он описывает свойства и методы будущих объектов.
Основные компоненты класса:
•	свойства - хранят данные;
•	методы - определяют действия;
•	конструктор - задаёт начальные значения;
•	getter-методы - позволяют получать значения свойств.
Например, класс Transaction описывает одну банковскую транзакцию.
3. Объясните, что такое полиморфизм и как он может быть реализован в PHP.
Полиморфизм - это возможность работать с объектами разных классов через общий интерфейс или родительский класс.
В PHP он реализуется с помощью интерфейсов и наследования.
В данной лабораторной работе TransactionRepository реализует интерфейс TransactionStorageInterface, а TransactionManager использует этот интерфейс для работы с хранилищем транзакций.
4. Что такое интерфейс в PHP и как он отличается от абстрактного класса?
Интерфейс определяет набор методов, которые должен реализовать класс.
Абстрактный класс может содержать абстрактные и обычные методы, свойства и конструктор.
Главное отличие заключается в том, что интерфейс определяет контракт поведения, а абстрактный класс может содержать общую реализацию.
5. Какие преимущества дает использование интерфейсов при проектировании архитектуры приложения? Объясните на примере данной лабораторной работы.
Интерфейсы делают архитектуру программы более гибкой и упрощают замену отдельных компонентов.
В данной работе TransactionManager зависит от TransactionStorageInterface, а не от конкретного класса TransactionRepository.
Благодаря этому можно создать другую реализацию хранения транзакций, которая будет поддерживать тот же интерфейс. При этом основную логику приложения не потребуется изменять.
